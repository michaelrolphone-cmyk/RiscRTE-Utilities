# Buttons actual Runtime fixture

The real Runtime, provider graph, ELF lifecycle, scene/HOLD provider and Buttons
application execute. The observer only copies state. Native navigation drives
Settings, assignment editing, exact HBv1 save to namespace 11, Reconnect, a
650 ms key hold (including 400 ms report refresh), release, Stop and Home.
The app actually unloads and reopens with its saved assignment. Three geometries
run demand, retained-provider, no-UI and alarm-reservation lanes. No-UI asserts
zero hardware/storage calls. The alarm lane doubles the public scheduler endpoint
and proves CUE reservation closes HID before the next output phase, then exact
occurrence dismissal. Normal/sanitized builds record per-TU compiler closure.

HID, display, touch/navigation and KV durability are endpoint doubles. Optional
Context/background and resident Home are absent in this fixture; separate focused
and shared-background proofs cover those contracts. This is not physical pairing,
Bluetooth host interoperability, full selected-product execution or deployment.
The scaffold derives from published Utilities 8e7b4df Scanner fixture; the Buttons
scenario and endpoints are new. Every failed intermediate log remains retained.
