# Contexts learning completion and activity (0.4.1)

The 0.4.0 UI's elapsed-time countdown could reach zero while the service waited without a deadline for three usable feature windows. The app never requested the resident shell's active-work sleep inhibition. The monochrome ring painted both completed and remaining portions black.

The app now shows recording progress, then a separate **Finishing capture** stage with animated activity and an accepted-window count if the service still needs evidence. It shows **Saving to library** before verified persistence and reaches **All set** automatically on success. A failed save keeps the captured profile available for an explicit retry. No-data and damaged-capture cases stop at 45 seconds with **Capture incomplete**, a source/policy explanation and Retry. Event learning remains three takes, bounded at 120 seconds. Normal idle behavior resumes after completion, cancellation or capture failure; active learning and save recovery inhibit idle and policy work. Training does not change the background Context Detection preference.

The shared presenter renders clockwise progress from twelve o'clock. Watch uses a dim track and rounded cyan arc; e-ink uses the bible's thin dashed guide and heavier partial arc. Indeterminate progress (maximum=0, value=0..2) provides reusable activity dots. Watch work screens keep status and Cancel in the viewport.

Validation includes the real timed RF service in full and RF-only builds (normal and ASan/UBSan), actual app_main with the production presenter on Watch and X4, input during pending frames, resident inhibit requests, automatic save, failed-save retry, bounded no-input failure and e-ink pixel checks. Normal RF completes at 30 seconds; a fixture that starts delivering RF at 22 seconds completes at 37 seconds; absent/gapped RF fails at 45 seconds. Existing 179 scene executions remain green. These are deterministic host fixtures, not measured room-recognition accuracy or physical-device tests.
